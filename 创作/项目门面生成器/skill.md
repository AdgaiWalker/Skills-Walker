# 项目门面生成器

以 README 为核心整理项目门面，一次走完生成 → 评测 → LICENSE → Git 收尾。

赶时间？跳到底部输出合同，看你要交什么。

---

## 核心原则

**人是决策者，AI 是执行者**：AI 负责分析、生成、整理、送审；人负责审核、放行、打回。

**先调查再动手**：启用后先调查仓库状态，推荐执行模式，不默认立刻改文件。

**一次确认，自动串行**：模式确认后，按预设策略自动推进，不每一步都停下来问。

**不越权**：AI 不代替用户做最终发布决策。

---

## 执行流程

```
1. 调查 → 仓库状态、README 现状、LICENSE、Git
2. 推荐模式 → 用户一次确认
3. 生成/优化 README → 主产物
4. README 评测 → 绿/黄/红放行
5. 视觉素材（按需）→ 仅发布档位且有明确意图时
6. LICENSE 处理 → 沿用或补齐
7. Git 收尾 → 提交和推送
8. 交付结果单
```

---

## 第一步：调查

启用后先快速调查，不直接进入写入。

调查项：

- 当前上下文是否充分（不足则先读关键文件补齐）
- 仓库形态：单项目 / 多项目 / 技能集合 / 文档库 / 模板资源
- 生成层级：仓库根 README / 子项目 README / 单个 skill README
- README 状态：已有需优化 / 缺失需生成
- LICENSE 状态：已有 / 缺失
- Git 状态：远程仓库、可提交改动、分支

上下文不足时，优先读取：顶层 README、项目定义文件（package.json 等）、主要源码目录。只读建立认知所需的关键文件，不无差别扫描。

---

## 第二步：推荐执行模式

根据调查结果推荐模式，用户只需做一次决策：

| 模式 | 什么时候用 |
|------|-----------|
| 审核后自动（默认） | 先给建议卡，用户确认一次后自动跑完 |
| 自动流 | 档位、LICENSE、推送策略都已明确 |
| 手动流 | 每个关键阶段都停下来确认 |

推荐表达应简洁：

```
推荐模式：审核后自动
README：需要重做 / 需要优化
LICENSE：沿用现有 / 建议补充
Git：远程明确，可自动推送
```

**决策项**（用户只需在开始时明确）：

- README 档位：快速 / 标准 / 发布
- LICENSE 策略：沿用 / 固定许可证 / AI 推荐
- 推送策略：不推送 / 只提交本地 / 自动推送

若用户表达了"正式发布""整理门面""推到远程"等意图，默认按发布模式执行。

---

## 第三步：README 生成/优化

### 项目类型判断

先判断类型，再选模板。常见类型：库/框架、CLI 工具、网站/应用、Skills、理论框架、文档/教程。

类型判断和 README 模板详见 [README框架总纲.md](README框架总纲.md)。

### 前半部分排序

不要写死一种顺序，优先回答目标读者最先关心的问题：

- **Skill / 工具 / 小产品**：有什么用 → 对谁有用 → 怎么用
- **知识 / 理论 / 教程**：解决什么问题 → 核心观点 → 能得到什么
- **工程 / 库 / 开源项目**：这是什么 → 能做什么 → 安装/快速开始

规则：先让用户判断"这是不是给我用的"，再展开原理。"设计原则"不抢第一屏。

### Skills 特殊规则

若目标是 Skills，默认补上：
- 安装方式（命令安装 + AI 帮装）
- 触发词
- 最短调用示例

能从上下文推断的信息直接补全，不追问。

### 参考与来源

不强行加到所有 README 结尾。仅在以下情况检查：
- 当前类型是 Skills 或理论框架
- 内容明确依赖外部资料、论文、官方文档、上游项目

有真实来源才写，不编造。放在正文结尾、License 之前。

### 美化风格

- **极简**：少徽章、少装饰、正文优先
- **标准**：适量徽章、清晰分节，可用"封面式开头"

已有 README 时：保留核心信息，调整结构和层级，补齐缺失内容，不做风格改写。

---

## 第四步：README 评测

README 生成后不直接继续，先评测放行。

评测标准详见 [各产物评测标准.md](各产物评测标准.md)。

核心检查：

- 是否先回答目标读者最关心的问题
- 是否写对仓库层级与项目类型
- 安装、使用、示例是否可执行
- 有无遗漏或过度承诺

评测结果：

| 结果 | 动作 |
|------|------|
| 绿色 | 通过，继续后续流程 |
| 黄色 | 自动修正一轮再复评 |
| 红色 | 停止，提示用户确认 |

---

## 第五步：视觉素材（仅发布档位）

仅在以下条件同时满足时才处理视觉素材：
- 当前是发布档位
- 用户明确需要视觉门面，或仓库已有可复用素材

做什么：
- SVG 标题、横幅或封面底稿
- 优先复用已有 Logo、截图、品牌素材
- 不凭空伪造复杂品牌系统

不需要视觉素材的项目（文档型交付）跳过此步。

SVG 动画衔接 `$svg-assembly-animator`，不在本 skill 内部发明动画逻辑。

---

## 第六步：LICENSE

处理原则：

- 仓库已有 LICENSE → 沿用，同步 README 中的 License 说明
- 仓库无 LICENSE 但策略已明确（如固定 MIT）→ 直接处理
- 缺失且策略不明 → 最小化确认一次

常见选项：MIT（宽松）、Apache-2.0（宽松+专利）、GPL-3.0（衍生需开源）、暂不添加。

处理完成后：生成/更新 LICENSE 文件，同步 README 中的 License 说明。

---

## 第七步：Git 收尾

前置条件：README 评测通过、视觉素材（如有）就绪、LICENSE 已处理。

检查项：
- 当前目录是否为 Git 仓库
- 是否有远程仓库和明确上游
- 是否有可提交改动
- 本次改动是否与其他改动能清晰区分

规则：
- 仅自动提交本次门面整理相关文件
- 远程目标明确则自动推送
- 工作区有无关改动或提交边界不清 → 停下来确认
- 远程不明、多个 remote、push 失败 → 最小化确认

---

## 输出合同

这个 skill 不只改一份 README，而是交付一份结果单。

### 最小交付

- 一份可用的 README
- README 评测结果：绿/黄/红
- 当前状态说明

### 标准交付

在最小交付基础上：
- 关键遗漏项说明
- LICENSE 处理结果：沿用 / 新增 / 暂不处理
- Git 处理结果：不处理 / 已提交 / 已推送

### 正式发布交付

在标准交付基础上（按需）：
- 视觉门面结果
- 发布包：当前已具备哪些对外发布材料

### 结果单格式

```
README：已完成 / 未完成 / 需复评
视觉门面：未启用 / 已复用 / 已新增 / 待后续
LICENSE：沿用 / 新增 / 未处理
Git：未处理 / 已提交 / 已推送
停止点：为什么停在这里
```
